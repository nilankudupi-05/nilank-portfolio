The problem: BoutiqBiz had three GenAI tools in development — Photoshoot Gen (swatch → model image), Style Gen (outfit reference → editorial look), Video Gen (image → product video) — and no PM to tie them together. Each tool had separate engineering assumptions, no shared prompt discipline, and an API cost model that turned out to be wrong.

The first thing I fixed was the cost model. The team had priced against Gemini API rates; the actual invoices would come through Vertex AI. I caught the ~36% gap during a pricing review and rebuilt the model before any commercial decision got anchored to the wrong number.

On the prompt side, I wrote v2 production templates with an explicit separation of concerns: reference images handle visual description only, Veo prompts handle motion and camera behaviour only. This eliminated the class of bugs where the model tried to infer motion from a static product swatch and hallucinated camera moves that didn't match the brief.

I ran weekly engineering reviews, scoped all feature briefs in Jira, and shipped a two-screen AI dashboard. Production bugs dropped 85%. The founder stopped triaging fires daily and started working on growth.

The original WKC participant flow was fragmented — discovery happened on Instagram, registration in a Google Form, confirmations over WhatsApp, and performance logistics in a spreadsheet. Nothing talked to anything else. Enrolment dropped between each step and nobody knew where.

I started by mapping the full journey from first touchpoint to a child walking onto the stage. Defined enrolment rate and completion milestones as the primary KPIs. Then rebuilt the flow: a single landing page, an inline registration form, automated confirmation sequences, and an admin layer the team could actually manage.

I designed and shipped showcases.wizkidscarnival.com — live in production, serving the Mumbai and Pune events. The site handles registrations, communicates event details, and converts parent interest at a measurably higher rate than the old fragmented flow.

In parallel I ran user interviews across three parent personas and rebuilt the free-to-paid conversion journeys around their specific hesitations. Revenue grew 30% in the first cycle the new journeys ran. Active users are up 80% — and unlike the old numbers, these are tracked, not estimated.

AI Contest Automation Pipeline

WKC was spending ₹40,000/month on contest content — freelancer time, coordinator review cycles, founder edits. Output was 20 contests/month but quality was inconsistent and the process couldn't scale. Every new contest format required starting from scratch.

I applied instructional design principles before touching any AI tooling. First I defined what a good contest looks like: age-group rules, format constraints, scoring rubric structure, quality standards. This became a structured policy document — not a prompt, but a codified decision framework.

That policy doc became the context layer fed to Gemini at inference time. The model generates contest briefs, rubrics, and scoring criteria against the constraints in the doc. Because the constraints are explicit, the outputs are consistent without extensive review.

Monthly content spend dropped from ₹40K to ₹5K — an 87% reduction. We maintained 20 contests/month. The remaining cost is one hour of human review per week, not a team of freelancers. The policy doc also made it trivial to add new contest formats: update the doc, the AI adapts, no retraining required.

The team was tracking Meta ad spend, quiz completions, and enrolment in three separate sheets. Correlating them meant manual copy-paste every Monday. Campaign decisions were made with a week's delay on data that was already stale.

I built a Claude-powered analytics dashboard to collapse this into a single view. No database — the tool is a four-tab React app where you upload a telemetry CSV and the dashboard does the rest: parses it, computes derived metrics (CPC, CPL, CTR), and routes the full dataset to Claude for AI-generated per-day commentary.

The key engineering decision was schema fingerprinting: Claude's CSV mapping runs once per schema structure and gets cached in localStorage. Subsequent uploads of the same format skip the AI call entirely. This kept API costs flat without degrading the experience for the team.

The Ask AI tab lets any team member query funnel performance in plain English — no SQL, no analyst, no two-day wait. The Recommendations tab surfaces action/watch/anomaly items from the full funnel context. Decision-making time on campaign performance went from days to minutes.

AI Approach

How I work with AI

Not "I use AI tools." I own the layer between the model and the person using the output. Here's what that looks like in practice.

⚙️
Prompt engineering with discipline
I write production templates, not one-off experiments. Reference images for visual description. Motion prompts for motion behaviour. Clear separation of concerns. v2 templates exist because v1 shipped, ran in production, and taught me something the spec couldn't predict.
💰
Cost modelling before launch
I build API cost models against official pricing before any feature ships — token counts, inference tiers, batch vs. real-time trade-offs. I've caught underestimates that would have destroyed margins. Cost is a product decision. It belongs in the spec, not the first invoice.
📄
Policy documents as decision brains
Structured policy docs injected as context — not just system prompts. They encode constraints, escalation rules, output standards, and edge case handling. This is what makes AI behaviour predictable enough to trust in production — and auditable enough to improve when it's wrong.
🔍
Outputs that are auditable by design
Every AI output in every product I've shipped surfaces its reasoning. Health briefs cite the specific usage event. Dashboard commentary references the data it drew from. If the team can't trace an AI recommendation back to a signal, it doesn't ship — regardless of how confident the model sounds.
